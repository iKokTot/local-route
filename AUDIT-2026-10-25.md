# Строгий аудит Local Route 0.26.7

Дата: 25 октября 2026. Аудит исходников и локальной сборки; не сертификат безопасности и не полноценный pentest.

## Объём и доказательства

Изучены main/preload, генератор sing-box, процессные операции Windows, хранилище, подписки, проверки сети, IPC и renderer. Повторно выполнены все 143 теста: 143 passed, 0 failed. Просмотрены свежие тестовые снимки VPN, Telegram и настроек. Проверены установленный Electron 39.8.10, отсутствие подписи установщика 0.26.7 и ACL установленного EXE: текущий пользователь имеет Full Control. Работающее соединение в ходе аудита не переключалось.

Не выполнены: проверка реальной утечки IPv6/DNS, испытания аварийного завершения, длительный нагрузочный прогон, измерение пропускной способности, все DPI-стратегии у разных операторов, Windows 7, аудит исходников внешних сетевых ядер. Скриншоты тестов используют mock API и не заменяют реальную Electron/TUN-проверку.

P1 — до расширения публичного распространения; P2 — следующий этап стабилизации; P3 — сопровождение. Риски отдельно обозначены: наличие опасного сочетания не равнозначно доказанному эксплойту.

## Приоритетные результаты

### A01 · P1 · Устаревшая платформа Electron — подтверждено

`node_modules/electron/package.json`: 39.8.10; `package.json`: ^39.2.7. Ветка 39 завершила поддержку 5 мая 2026 по официальному расписанию: https://releases.electronjs.org/schedule . На дату аудита она EOL. Это не утверждение об эксплуатации конкретной CVE.

Действие: перейти на поддерживаемую стабильную ветку отдельным изменением, закрепить точную версию, проверить preload/sandbox, safeStorage, установку, автозапуск и стартовые задержки. Добавить регулярный контроль EOL и зависимостей.

### A02 · P1 · Повышенные права сочетаются с изменяемыми пользователем бинарниками — подтверждённый риск

`scripts/embed-icon.js`: requireAdministrator; `src/core/autostart.js`: /RL HIGHEST; `electron-builder.json`: perMachine false; ACL установленного Local Route.exe допускает запись текущему пользователю. EXE и внешние ядра запускаются из пользовательского каталога. Код не проверяет подписи/хэши ядер перед запуском.

При существующей повышенной задаче замена исполняемого файла в доступном для записи каталоге создаёт опасный путь повышения привилегий. Эксплойт не выполнялся, ACL самой задачи отдельно не исследовался.

Действие: непривилегированный renderer/основное приложение + минимальный elevated helper/service, защищённый каталог его установки, строгий локальный IPC, проверка версий и доверия ядер. Не пытаться решить одной сменой текста UAC.

### A03 · P1 · VPN «запущен» не означает, что сеть работает — подтверждено

`src/main.js` startVless и `src/core/runtime-readiness.js`: готовность определяется локальным TCP listener. Внешняя HTTPS-проверка выполняется отдельно вручную. При таймаутах удалённого сервера процесс остаётся активным; текущая ошибка VPN не обновляется по этим событиям. Запись warn/error в лог не является health state.

Действие: отдельные состояния процесса, маршрутов и внешнего соединения; последнее время проверки, устаревание результата, ограниченный health-monitor с backoff. Не объявлять каждое краткое сетевое прерывание аварией. Проверять состояние после смены сети, а не только после resume.

### A04 · P1 · Реальные маршруты остаются недостаточно проверенными — подтверждённый пробел тестов

`test/vpn-exclusions.test.js`: полезный настоящий sing-box, но без реального TUN, с loopback HTTP/DNS; `test/ui.test.js`: mock API; `test/network-controls.test.js`: подменяются процессы, readiness и trustedEvent. DNS-исправление Авито показывает, почему этих тестов недостаточно.

Действие: отдельный разрешаемый пользователем Windows E2E-стенд: исходный IP вне VPN, IP через VPN, исключённый тестовый домен на контролируемом сервере, IPv4/IPv6, HTTPS/QUIC, обычный DNS/DoH, смена адаптера, sleep/resume, перезапуск и недоступный сервер. Реальные токены не хранить в CI-логах. Не использовать публичную антибот-страницу как единственный эталон.

### A05 · P1 · Не определён гарантированный жизненный цикл ядер при падении оболочки — риск

`src/main.js`: обычные spawn и штатный before-quit; `src/platform/windows.js`: остановка отслеживаемых children. Windows Job Object с kill-on-close отсутствует. Для DPI есть отдельный поиск процессов восстановления; аналогичного полноценного восстановления VPN/TG нет. Падение или принудительное завершение оболочки не запускает before-quit.

Действие: выбрать явный контракт «ядра завершаются вместе с приложением» либо управляемый фоновый сервис; реализовать supervisor, recovery и проверку владения процессами. Не убивать чужой sing-box по одному имени процесса.

### A06 · P2 · Ошибка семантики замера скорости — подтверждено кодом

`src/core/vless-check.js`: при downloadBytes и statusCode != 200 вызывается responseResult. Например, 204 или 302 дают success=true без проверки 10 МБ, после чего checkProxySpeed сообщает о завершённом замере.

Действие: для скорости принимать только ожидаемый HTTP 200 и точный объём; все остальные статусы — отдельный отказ замера. Не менять общую семантику проверок доступности сайтов. Добавить тесты 204/302/206/429 и неверного размера.

### A07 · P2 · DPI-проверки завышают смысл подтверждения — подтверждено

`src/main.js` probe: HTTP 200–499 считаются success. Это допускает 403/404/429; ручной тест сохраняет verifiedStrategy при успехе и останавливает движок в finally. Автоподбор также сохраняет verifiedStrategy по HTTP-пробам, не проверяя видео YouTube и голос Discord.

Действие: разделить «TCP/TLS доступен», «endpoint отвечает ожидаемо» и «пользователь подтвердил работу». Для каждого endpoint задать ожидаемые статусы. В ручном режиме явно сообщать «тест завершён, DPI остановлен» либо оставлять кандидата до подтверждения. Старое рабочее подтверждение не терять до успешного нового.

### A08 · P2 · Один глобальный busy мешает независимым компонентам — подтверждено

`src/core/operations.js`, `src/main.js` managedChannels и `src/renderer/app.js` renderControls: операция одного компонента блокирует действия других. Локальная остановка VPN запрещена при busy; глобальная остановка доступна, но останавливает всё.

Действие: отдельные очереди DPI/VPN/TG и явная общая блокировка только для реального изменения маршрутов. Stop/cancel должен иметь приоритет над обычными действиями. Не снимать все блокировки без модели зависимостей: DPI меняет VPN direct-домены.

### A09 · P2 · Политика DNS/исключений требует завершения — подтверждённые ограничения

`src/core/vless.js`: один прямой DoH 1.1.1.1 без альтернативы; его недоступность затрагивает прямое разрешение и bootstrap имён VPN-сервера. Исключения по доменам требуют видимого DNS/имени; собственный DoH/ECH приложения может обходить эту привязку. По имени .exe исключается любой одноимённый процесс. FakeIP-кэш сохраняет домены на диске.

Действие: управляемый набор DNS-серверов с раздельными direct/VPN каналами и безопасным fallback, без возврата к рекурсивному системному DNS. Документировать доверие к резолверу и локальный кэш. Добавить объяснение конкретного маршрута и инструменты проверки исключений. Не обещать полноту CDN-каталогов и не добавлять широкие IP-подсети вслепую.

### A10 · P2 · Приватность при отказе и IPv6 не оформлены как контракт — подтверждённое поведение + непроверенный риск

При завершении VPN показывается предупреждение о возможном прямом трафике, но firewall kill switch нет. Это существующий fail-open, не случайно обещанный fail-closed. IPv6 TUN включается только после эвристики в `src/core/network.js`; её отказ не доказывает отсутствие других IPv6-путей. Конкретная утечка в аудите не установлена.

Действие: явно назвать режим отказа в настройках; до обещаний защиты проверить IPv6, DNS, исключения и LAN на двухстековой сети. Kill switch делать отдельным проектом с гарантированным откатом, не добавлять неподготовленные постоянные firewall-правила.

### A11 · P2 · Синхронная работа в main и большие перерисовки — подтверждённая архитектурная стоимость, не измеренное торможение

`src/core/state-store.js`: sync read/write/fsync/rename; `src/main.js` publicState расшифровывает и пересобирает всю библиотеку, читает состояние многократно; `src/renderer/app.js`: периодический refresh перерисовывает списки. До 16 подписок, до 500 серверов на один импорт. Это не означает, что сейчас доказана потеря скорости интернета.

Действие: замерить p50/p95 задержек IPC и event-loop на большой библиотеке; кешировать нормализованное состояние, версионировать изменения, делать async последовательные записи, обновлять UI по изменённым данным, виртуализировать длинные списки. Сохранять атомарность и резервную копию.

### A12 · P2 · Сборка не воспроизводится одной командой с чистого checkout — подтверждено текущим процессом

Проверочные установщики собирались через копию предыдущего prepackaged каталога с заменой файлов. Нет .github CI и штатного полного build-скрипта в package.json. electron-builder.json содержит номер версии в output; сторонние engine-артефакты не закреплены единым проверяемым manifest. Подпись установщика 0.26.7 — NotSigned.

Действие: отдельная чистая staging-директория, автоматическое включение только разрешённых файлов, manifest версий/хэшей/источников/лицензий, проверка содержимого установщика, Windows CI, подписанные артефакты и smoke-тест установки/обновления/удаления. Не публиковать recovery-скрипты и локальные настройки автоматически.

### A13 · P2 · Проверки и архитектура дублируются — подтверждено

Два загрузчика подписок: `core/subscriptions.js` используется приложением и имеет строгие редиректы; `core/subscription-formats.js` экспортирует ещё один fetchSubscription с другой политикой. Риск будущего использования менее строгого кода. Диагностический createVlessCheckConfig по-прежнему использует local DNS, в отличие от рабочего TUN-конфига. «Проверка сервера» и реальное соединение могут расходиться по DNS.

Действие: один загрузчик с transport policy, один генератор DNS-policy с разными профилями маршрутизации. Не удалять различия диагностического режима, которые намеренно заставляют его идти только через VPN.

### A14 · P2 · Секрет Telegram присутствует в аргументах процесса — подтверждено

`src/main.js` startTelegram: --secret передаётся в spawn. Маскирование журнала и шифрование на диске не скрывают командную строку от процессов с достаточными правами. Прокси слушает только loopback, что ограничивает воздействие.

Действие: передавать через stdin/унаследованный канал, если ядро позволяет, либо изменить console wrapper; не писать секрет в временный открытый файл. Ограничение модели угроз описать честно.

## Интерфейс

Просмотренные тестовые страницы аккуратно выровнены, явного горизонтального переполнения на них нет. Не стоит заполнять свободное место декоративными блоками.

- P2: постоянный статус должен различать «процесс запущен», «сеть проверена», «проверка устарела», «ошибка», а не только зелёную карточку.
- P2: причины disabled нужны видимым текстом у группы действий: title недоступен при наведении на части disabled-контролов и не заменяет сообщение для клавиатуры/тача.
- P2: сохранение исключений требует stop/save/start. Нужен безопасный единый сценарий «Применить и переподключить» с явным предупреждением об обрыве.
- P2: «Запустить всё» фактически запускает выбранный набор. Назвать «Запустить выбранное» или показывать состав рядом.
- P3: при собственном фоновом обновлении сохранять фокус/раскрытые списки; проверять keyboard navigation, 125/150/200% масштаб и длинные подписи, а не только ширину viewport.
- P3: кнопки «Проверить подключение» и «Качество соединения и результаты» объединить понятной иерархией: действие наверху, краткий последний результат рядом, подробности ниже.

## Что сделано хорошо

Sandbox, contextIsolation, локальная CSP и запрет навигации; проверка sender/mainFrame у IPC; список разрешённых внешних ссылок. safeStorage, исключение секретов из publicState и allowlist диагностического экспорта. Атомарные записи/backup без молчаливого сброса повреждённых настроек. Ограничения размера и времени загрузок, отмена операций, явный VPN CONNECT без direct fallback. Свёртывание сложных настроек и адаптивные UI-тесты. Ротация журнала есть; утверждать, что лог не ограничен, было бы неверно.

## Масштабирование без переписывания всего

1. Стабилизация: A03/A06/A07/A09, реальные route E2E, воспроизводимая сборка и поддерживаемый Electron.
2. Безопасная архитектура: privileged helper, supervisor, состояние каждого компонента как state machine. Вынести из main.js VPN/DPI/TG/subscriptions/IPC в отдельные сервисы.
3. Общие контракты: runtime-валидация IPC и state, schema migrations, единые коды ошибок; типы через TypeScript или JSDoc/checkJs постепенно.
4. Рост: отдельные component queues, версионированное состояние, большие библиотеки/виртуализация, метрики без секретов. Не добавлять новые протоколы раньше проверки жизненного цикла и маршрутов.

## Критерии готовности следующего стабильного релиза

- Не только 143 зелёных теста, но и задокументированные результаты route E2E, sleep/network-switch/crash и установки/удаления.
- Поддерживаемый runtime, проверяемые engine-артефакты, повторяемая сборка из чистого checkout.
- «Работает» подтверждается проверкой соединения с временем, а «запущен» обозначает только процесс.
- Исключения и IPv6 проверены независимо от встроенного HTTP health-порта.
- Нет незаявленной смены политики приватности; режим отказа понятен пользователю.

Итог: работоспособная beta с полезными защитными мерами; не готовая к обещаниям гарантированной приватности или масштабному распространению без следующего цикла стабилизации. Переписывать всё с нуля оснований нет. Код приложения этим аудитом не изменялся.
