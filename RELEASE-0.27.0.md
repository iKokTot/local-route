# Local Route 0.27.0 — кандидат стабилизации

- Electron обновлён с 39.8.10 до точно закреплённого 44.9.3.
- Скорость считается измеренной только при HTTP 200 и получении полного тестового файла. 204/206/редиректы/HTTP-ошибки не считаются успешным замером.
- Для DPI заданы ожидаемые статусы конкретных диагностических адресов. Общая политика «любой HTTP до 499 — успех» убрана; HTTP 403/404 допускаются только там, где это ожидаемый ответ технического адреса, а не подтверждение видео/голоса.
- Ручная DPI-проверка явно сообщает, что движок после теста остановлен. Windows-индикатор больше не называет HTTP-проверку пользовательским подтверждением.
- Появился отдельный статус внешнего HTTPS через запущенный VPN: время проверки, недоступность, устаревание. Проверка начинается после запуска, обычно повторяется через 30 секунд и реже при ошибках (до 5 минут). Она не проверяет весь TUN, исключения или приложения и не меняет выбранный сервер.
- Запоздалый ответ фоновой проверки не может восстановить статус остановленного VPN. Сон инвалидирует проверку; изменения набора интерфейсов вызывают перепроверку.
- Локальная кнопка остановки VPN может отменить незавершённый запуск, не выключая DPI.
- Рабочий и диагностический sing-box используют общую политику DNS без обращения к рекурсивному системному DNS внутри TUN.
- Совместимый старый загрузчик подписок использует единую политику HTTPS, редиректов, таймаутов и размера.
- Кнопка обзора точнее называется «Запустить выбранное».
- Сборка из чистого staging-каталога, проверяемый manifest ядер и build-info. Добавлен Linux unit/UI workflow; удалённый CI пока не запускался, Windows TUN этим workflow не проверяется.

Проверено локально: 151 автоматический тест; настоящий Electron 44 с временным профилем, preload, sandbox/contextIsolation, шифрованием safeStorage и открытием страницы VPN. Проверки не включали реальное переключение установленного приложения, его аварийное завершение или внешний сетевой E2E.

Исправлены четыре low/moderate предупреждения одного транзитивного build-пакета fast-uri закреплением 3.1.9. После обновления pnpm audit сообщил 0 известных уязвимостей npm-зависимостей. Это не включает полноценный аудит внешних ядер и не является гарантией безопасности.

Остаются открытыми: разделение привилегий, supervisor/Job Objects и восстановление после падения, реальный IPv6/DNS/TUN стенд, необязательный kill switch, многокомпонентные очереди, UI применения исключений с переподключением, профилирование больших подписок и подпись установщика. Не обещаем, что все пункты аудита уже закрыты.

Фоновая HTTPS-проверка обращается к Cloudflare через VPN; direct DNS использует Cloudflare DoH вне VPN. FakeIP-кэш доменов хранится локально. Режим аварийного отказа остаётся fail-open с предупреждением; гарантии блокировки прямого трафика нет.

Установленную копию автоматически не заменяли. Публикация не выполнялась.
