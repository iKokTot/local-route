# Local Route 0.28.0 — кандидат стабилизации, этап 2

- Запуск DPI, VPN, Telegram-прокси и диагностического VPN через собственный Windows ProcessHost. Новое ядро создаётся уже принадлежащим Job Object, до выполнения его кода; при завершении владельца или надсмотрщика дерево завершается Windows. Передаются только необходимые stdio handles. При невозможности создать защиту не применяется молчаливый незащищённый запуск.
- При штатной остановке дополнительно ожидается завершение собственного ядра: выход надсмотрщика ещё не означает, что старый TUN уже освобождён.
- Фактический PID winws отличается от PID надсмотрщика; обнаружение внешних winws учитывает оба и не принимает собственное ядро за чужое.
- Убрана повторная расшифровка неизменившейся библиотеки при обновлении UI. Кэшируется замороженная публичная проекция, без URI/токенов. Изменение списка/выбора сбрасывает кэш; ошибка расшифровки не превращается в закэшированный пустой список.
- После сна успешная свежая проверка убирает именно предупреждение resume, но не чужую постоянную ошибку.
- У групп кнопок появились видимые пояснения; title у disabled больше не единственный источник причины блокировки.

Проверка supervisor: настоящие процессы Windows, stdin, Unicode/пробелы/кавычки/пустые аргументы, exit code, завершение target и grandchild при падении owner и при завершении guard. Настоящий sing-box проверен через ProcessHost на loopback HTTP/DNS без TUN. В isolated Electron smoke подтверждено завершение его тестового дочернего процесса без штатного recovery shutdown.

Итоговые локальные проверки: 158 тестов прошли, runtime smoke прошёл; TGWs через ProcessHost с `--help` завершился с кодом 0. pnpm audit — 0 известных npm advisories. Существующий пользовательский VPN в ходе этих проверок не перезапускался.

Локальный микрозамер на пяти запусках короткого Node fixture: median direct 61 мс, через guard 117 мс, добавка 56 мс. Это не время запуска настоящего VPN и не обещание отсутствия затрат RAM или холодного старта после входа в Windows.

Ограничения: ProcessHost работает с теми же правами, что приложение, и НЕ закрывает разделение административных привилегий. Не проверено аварийное восстановление реального TUN/WinDivert на рабочей сети; DNS-кэш ОС/браузера после аварии требует отдельного испытания. Остаются открытыми пункты STABILIZATION-STATUS.md.
